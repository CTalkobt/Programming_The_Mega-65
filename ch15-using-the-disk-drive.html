Programming the MEGA65 — Chapter 15: Using the Disk Drive

Oct 4, 2026 · Updated Nov 13, 2026 · @Craig Taylor

Disk image: ch15.d81 holds this chapter's 10 complete programs. Each can also be downloaded from the links above its listing, and every listing has a Copy button.

Introduction

Most of this chapter applies equally to a disk image on the SD card, the MEGA65's internal 3.5" drive and a Commodore drive on the IEC port. All three speak Commodore DOS, so ordinary file handling written for one works on the others. The MEGA65's own DOS adds features an older drive lacks, such as partitions; the text notes where that matters. Chapter 14 explained images and unit numbers; this chapter covers the drive itself, files of each type with worked examples, the drive's status, the housekeeping commands that copy, rename, delete and recover files and tidy whole disks, and disk access from machine language.

Drives, Units and Drive Numbers

Every drive is reached through a unit number. Units 8 to 11 are reserved for disk drives, and BASIC 65's disk commands use unit 8 unless given a U argument. A unit assigned to a disk image or to the internal drive is handled inside the MEGA65; any other unit number is sent to the IEC port, where the device with that number answers (MEGA65 Book, p. 6-3). Managed drives and unit numbers in Chapter 14 explains the two managed drives and how to mount images on them and change their numbers.

The D argument selects a drive within a unit. It is needed only for old dual-drive units such as the Commodore 4040 or 8050, where the second drive is drive 1; every other drive is drive 0.

The internal 3.5" drive

The internal drive behaves as a Commodore 1581 and reads and writes 1581-format disks. It must be mounted before use: in the Freezer, choose the first managed drive and select INTERNAL 3.5", or type MOUNT with no arguments in BASIC to mount it as unit 8 (MEGA65 Book, pp. 6-6, 6-7).

The drive expects Double Density (DD) disks. High Density disks work if both sides of the density hole, top left when viewed from the front, are covered with tape, which makes the drive treat them as DD (MEGA65 Book, pp. 6-7, 6-8).

To format a disk, mount the drive as unit 8, insert the disk and give it a name and a two-character ID:

FORMAT "MYDISK", IXX

When asked ARE YOU SURE?, type YES and press RETURN. Formatting takes about a minute; afterwards, DIR shows an empty directory with the new name and ID.

IEC drives

External drives such as the 1541, 1571 and 1581, and modern devices such as SD2IEC and Pi1541, plug into the IEC port and need no mounting. If one needs a unit number the MEGA65 has given to a managed drive, use the Freezer's 8 and 9 keys to move the managed drive to 10 or 11 (MEGA65 Book, p. 6-9).

In C64 mode, release CAPS LOCK before loading from an IEC drive: it forces full CPU speed, which upsets the C64 KERNAL's bus timing. Chapter 8 explains this under Things that change speed for you.

Files

File types

Type Contents Used with
PRG A program or memory block, starting with a two-byte load address DLOAD, DSAVE, BLOAD, BSAVE, RUN
SEQ Sequential data, read and written from start to end DOPEN, PRINT#, INPUT#, APPEND
USR Sequential data like SEQ, with a different type in the directory; see USR files DOPEN or OPEN with ,U in the name, APPEND
REL Relative file of fixed-length records, read in any order DOPEN with L, RECORD
CBM A 1581 partition, used for subdirectories MKDIR, CHDIR (internal drive and disk images only, not IEC drives)

Sequential files

A sequential file is written with PRINT# and read back with INPUT# or LINE INPUT#, in the same order. Separate fields with commas, or write each on its own line, so INPUT# can tell where one ends:

10 DOPEN#2, "SCORES", W
20 IF DS THEN PRINT DS$ : STOP
30 FOR I = 1 TO 3 : READ N$, S : PRINT#2, N$ "," S : NEXT
40 DCLOSE#2
50 DATA ALICE, 1200, BOB, 900, CAROL, 1500
100 DOPEN#2, "SCORES"
110 DO : INPUT#2, N$, S : PRINT N$, S : LOOP UNTIL ST
120 DCLOSE#2

ST becomes non-zero when the last item has been read. Adding to an existing file uses APPEND# instead of DOPEN#, and replacing a file needs it to be scratched first, or an @ before the name, which works for data files as well as programs, as in DOPEN#2, "@SCORES", W (MEGA65 Book, DOPEN). If the file does not exist, the @ has no effect and the file is created as usual.

The Book advises against @ on 1541 and 1571 drives, because of the "save-and-replace" bug in their DOS, which can corrupt a disk. A MEGA65 Filehost article, cited below, reports the bug in every Commodore drive from the 2040 to the 1581. Whichever drives have it, a program cannot tell what is on the IEC port, so the safe rule is to avoid @ on any external drive and scratch the old file first. The MEGA65's own DOS does not have the bug. It was fixed in ROM 920303, and from 920361 @ also works when saving from EDIT mode (MEGA65 ROM change log). On the internal drive and on disk images, DSAVE, SAVE, DOPEN and OPEN all accept it, as in OPEN 2,8,2, "@SCORES,S,W" (MEGA65 Filehost, "DOS - Tip: save-and-replace bug").

Example: a notes file

This program adds a line to a file of notes each time it runs, then lists the whole file. APPEND# fails with 62, FILE NOT FOUND the first time, before the file exists, so the program then creates it with DOPEN and W. A failed APPEND# or DOPEN still leaves its channel number in use, so DCLOSE it before opening it again, or the second open stops with ?FILE OPEN ERROR. Line 40 relies on DOPEN clearing the status that line 30 read, which it does from ROM 920404 (MEGA65 ROM change log); Drive status explains:

10 LINE INPUT "NOTE: "; N$
20 APPEND#2, "NOTES"
30 IF DS = 62 THEN DCLOSE#2 : DOPEN#2, "NOTES", W
40 IF DS THEN PRINT DS$ : DCLOSE#2 : END
50 PRINT#2, N$
60 DCLOSE#2
70 DOPEN#2, "NOTES"
80 DO : LINE INPUT#2, L$ : PRINT L$ : LOOP UNTIL ST
90 DCLOSE#2

LINE INPUT and LINE INPUT# take a whole line, commas and colons included, where INPUT# would stop at the first comma. That suits free text; for files of separate values, such as the scores above, INPUT# and commas are the better choice.

Example: a high-score table

A game keeps its best ten scores in arrays while it runs, reads them from disk at the start, and writes them back after each game. When the file is missing, as it is the first time, DS is not 0 after DOPEN and the program keeps the empty table it has just made. Saving uses @ to replace the old file in one step, so it is meant for the internal drive and disk images; on an IEC drive, scratch the old file first:

10 DIM N$(9), S(9)
20 FOR I = 0 TO 9 : N$(I) = "NOBODY" : S(I) = 0 : NEXT
30 DOPEN#2, "HISCORES"
40 IF DS = 0 THEN FOR I = 0 TO 9 : INPUT#2, N$(I), S(I) : NEXT
50 DCLOSE#2
60 FOR K = 1 TO 3 : READ NM$, SC        : REM THREE NEW SCORES
70 IF SC <= S(9) THEN 120               : REM NOT GOOD ENOUGH
80 P = 9
90 DO WHILE P > 0 : IF S(P - 1) >= SC THEN EXIT
100 N$(P) = N$(P - 1) : S(P) = S(P - 1) : P = P - 1 : LOOP
110 N$(P) = NM$ : S(P) = SC
120 NEXT
130 DOPEN#2, "@HISCORES", W
140 FOR I = 0 TO 9 : PRINT#2, N$(I) "," S(I) : NEXT
150 DCLOSE#2
160 FOR I = 0 TO 9 : PRINT I + 1, N$(I), S(I) : NEXT
170 DATA ALICE, 1200, BOB, 900, CAROL, 1500

Lines 80 to 110 find the new score's place, moving each lower score down one place. Run the program a second time with different DATA and the table read from disk merges with the new scores. Starting every name as NOBODY rather than an empty string means every line of the file has something before its comma.

USR files

A USR file is a sequential file with a different type in the directory. The DOS stores and reads it exactly as it does a SEQ file: the type is just a number in the file's directory entry, 1 for SEQ and 3 for USR, and only REL files and partitions get special treatment (MEGA65 ROM source, dos.src). PRINT#, INPUT#, GET#, APPEND# and COPY all work on USR files as on SEQ files (MEGA65 Book, pp. B-20, B-59). TYPE is the exception: the Book says it shows USR files too (p. B-270), but it asks the DOS for a SEQ file, so on a USR file it stops with 64, FILE TYPE MISMATCH (MEGA65 ROM source, TYPE; tested with ROM 920422).

The type is a label. A program can give its own data files the USR type so that they stand apart from ordinary text files in a directory listing, and so that a pattern can pick them out: DIR "*=U" lists only USR files, and =S, =P and =R do the same for the other types.

DOPEN creates a SEQ file unless told otherwise, so add ,U to the name to create a USR file. With OPEN, the type letter goes before the mode letter, as in ,S,W for a sequential file (MEGA65 Book, DOPEN):

10 DOPEN#2, "LEVELS,U", W
20 PRINT#2, "LEVEL ONE" : DCLOSE#2
30 APPEND#2, "LEVELS,U"
40 PRINT#2, "LEVEL TWO" : DCLOSE#2
50 OPEN 2, 8, 2, "LEVELS,U,R"
60 DO : INPUT#2, L$ : PRINT L$ : LOOP UNTIL ST
70 CLOSE 2

When reading, the MEGA65's DOS also finds the file without the ,U: DOPEN#2, "LEVELS" opens it.

Relative files

A relative file holds numbered records of a fixed length, given with L when the file is first created. RECORD moves to any record directly, which suits indexes, high-score tables and small databases where a sequential file would have to be read from the start:

10 DOPEN#3, "PLAYERS", L20
20 RECORD#3, 5 : PRINT#3, "PLAYER FIVE"
30 RECORD#3, 2 : PRINT#3, "PLAYER TWO"
40 RECORD#3, 5 : INPUT#3, A$ : PRINT A$
50 DCLOSE#3

Each record must fit its length, including the carriage return PRINT# adds.

Example: a stock list

A relative file makes a simple database when each record has a number that identifies it, such as a part number. This program keeps a stock list. The first time it runs it creates the file and writes four parts; every time, it looks up one part and changes its quantity. Each record holds a name and a number separated by a comma, so INPUT# can read them back as two fields. PRINT# writes a number with a space or a minus sign in front and a space after it, so a length of 24 leaves room for a name of up to 16 characters, the comma, a quantity of up to four digits with its two spaces, and the carriage return:

10 DOPEN#3, "STOCK", L24
20 IF DS THEN PRINT DS$ : STOP
30 RECORD#3, 1 : INPUT#3, N$
40 IF ASC(N$) <> 255 THEN 100          : REM THE PARTS ARE ALREADY THERE
50 FOR R = 1 TO 4 : READ N$, Q
60 RECORD#3, R : PRINT#3, N$ "," Q
70 NEXT
80 DATA BOLTS, 120, NUTS, 300, WASHERS, 75, SCREWS, 40
100 INPUT "PART NUMBER"; R
110 RECORD#3, R : INPUT#3, N$, Q
120 IF ASC(N$) = 255 THEN PRINT "NO SUCH PART" : GOTO 160
130 PRINT N$; Q; "IN STOCK" : INPUT "CHANGE BY"; C
140 RECORD#3, R : PRINT#3, N$ "," Q + C
150 IF DS THEN PRINT DS$
160 DCLOSE#3

Reading a record moves the file on to the next one, so line 140 gives RECORD again before writing the changed record back in the same place. The DOS fills a new relative file to the end of its last block with empty records, and an empty record reads back as the single character CHR$(255), with any further variable in the INPUT# left empty or 0 (tested in Xemu with ROM 920413). Line 40 uses this to tell a new file from one that already holds its parts, so running the program again keeps the quantities changed earlier, and line 120 uses it to spot a part number that was never written. Once the file exists, DOPEN#3, "STOCK", L opens it without giving the length again (MEGA65 Book, DOPEN).

RECORD numbers start at 1. Positioning beyond the last record and writing there makes the DOS extend the file with empty records, as long as the disk has room (MEGA65 Book, p. B-206).

Reading the directory from a program

DIR prints the directory but gives a program nothing to work with. To get the names into variables, open the directory as a file: OPEN 1,8,0,"$". Secondary address 0 asks for it in the same form LOAD "$" produces, a BASIC program with one line per entry: each line starts with a two-byte link and a two-byte line number, which holds the file's size in blocks, then the text of the line and a zero byte. The first line is the disk name and ID, and the last is BLOCKS FREE (MEGA65 ROM source, dos.src). This program reads it into arrays:

10 DIM N$(296), T$(296), B(296) : C = -1
20 OPEN 1, 8, 0, "$"
30 GET#1, A$, A$                    : REM SKIP THE LOAD ADDRESS
40 DO
50 GET#1, A$, A$ : IF ST THEN EXIT   : REM LINK; END OF DIRECTORY
60 GET#1, L$, H$ : BL = ASC(L$) + 256 * ASC(H$)
70 L$ = ""
80 DO
90 GET#1, A$ : IF ASC(A$) THEN L$ = L$ + A$
100 LOOP WHILE ASC(A$)
110 Q = INSTR(L$, CHR$(34)) : IF Q = 0 THEN FR = BL : EXIT
120 R = INSTR(L$, CHR$(34), Q + 1)
130 C = C + 1 : N$(C) = MID$(L$, Q + 1, R - Q - 1) : B(C) = BL
140 F$ = MID$(L$, R + 1)
150 DO WHILE LEFT$(F$, 1) = " " : F$ = MID$(F$, 2) : LOOP
160 T$(C) = F$
170 LOOP
180 CLOSE 1
190 PRINT "DISK: "; N$(0); "  ID: "; T$(0)
200 FOR I = 1 TO C : PRINT N$(I), LEFT$(T$(I), 4), B(I) : NEXT
210 PRINT C; "FILES,"; FR; "BLOCKS FREE"

Each line is collected into L$; the name is whatever lies between the first two quotation marks, and the rest, with leading spaces removed, is the type. The BLOCKS FREE line has no quotation marks, which ends the loop. Element 0 of the arrays holds the disk name, padded with spaces to 16 characters, and the ID, which is followed by the DOS type, 1D on a disk formatted by the MEGA65. The arrays have room for the 296 entries a 1581 directory can hold; a 1541 disk holds 144. Line 200 prints four characters of the type so that the * of an unclosed file, described next, does not push the last letter off. BASIC 65's ASC returns 0 for an empty string, so the program works whether GET# returns a zero byte as CHR$(0) or as an empty string.

The type text can carry markers: * before the type for a file that was never properly closed, and < after it for a locked file (MEGA65 ROM source, dos.src). The name may include a pattern, as with DIR: "$0:M*" reads only names beginning with M, and "$0:*=S" only SEQ files.

Drive status

Every disk operation leaves a status in the drive, which BASIC 65 reads into DS and DS$. DS$ has the form code, message, track, sector. Codes below 20 mean success; the common ones are:

Code Meaning
00 OK
01 Files scratched (the track value gives how many)
03, 04 Files locked, files unlocked (the track value gives how many)
05 Files restored after scratching (the track value gives how many)
02 Selected partition: CHDIR has changed the directory (the track and sector values give its first and last track)
20-29 Read or write errors: the disk is damaged, unformatted or write-protected
25 Write error: a block read back after writing did not match
26 Write protect on
30-34 Syntax error in a command string or a file name
50 Record not present: a relative file was positioned past its last record
51 Overflow in record: more was written than a relative record holds
52 File too large: no room to extend a relative file
60 Write file open: the file is still open for writing
61 File not open
62 File not found
63 File exists
64 File type mismatch: the file exists, but with another type
66 Illegal track or sector
70 No channel: too many files are open on the drive
72 Disk full
73 The DOS's name and version: the message after power-on or a reset, not an error
74 Drive not ready: no disk
75 Format error

These are the standard Commodore DOS codes, which the MEGA65's drives share with the 1581; codes 03 to 05 come from the MEGA65's own DOS, which has the commands that produce them (MEGA65 ROM source, dos.src). Checking DS after each DOPEN and save is the single most effective way to make a program that uses disks reliable.

DS is not always fresh. BASIC 65 reads the message from the drive the first time DS or DS$ is used and then keeps it, until a command throws the kept copy away. OPEN and DOPEN do that, DOPEN only from ROM 920404 (MEGA65 ROM change log), so the examples above are safe on current ROMs. The housekeeping commands in the next section do not when they run in a program, so DS after one of them can still show the result of an earlier command. CLR DS, a form of CLR the MEGA65 inherited from the C65, throws the kept message away, and the next use of DS reads the drive afresh (MEGA65 ROM source, clear, Clear_DS). The command channel has an example.

Disk Housekeeping

On the C64, every housekeeping job, from deleting a file to formatting a disk, meant sending a command string to the drive's command channel. BASIC 65 has a keyword for each, which builds the command string and sends it for you. The table gives both; the command strings are the ones BASIC 65 sends, with drive number 0 (MEGA65 ROM source, tabld). Chapter 3 lists the full syntax of each keyword. BACKUP U8 TO U9, between the two managed drives, has no command string: the MEGA65 copies the disk itself, as described under Formatting and copying whole disks.

Task BASIC 65 Command string
Copy a file COPY "OLD" TO "NEW" C0:NEW=0:OLD
Join two SEQ files CONCAT "MORE" TO "ALL" C0:ALL=0:ALL,0:MORE
Rename a file RENAME "OLD" TO "NEW" R0:NEW=0:OLD
Scratch (delete) files SCRATCH "OLD", also DELETE and ERASE S0:OLD
List scratched files DIR R _, opened like $
Recover scratched files SCRATCH "OLD", R F-R0:OLD
Lock, unlock files LOCK "NAME", UNLOCK "NAME" F-L0:NAME, F-U0:NAME
Validate a disk COLLECT V0
Initialise a drive DCLEAR I0
Format a disk HEADER "NAME", IID, also FORMAT N0:NAME,ID
Copy a whole disk in a dual drive BACKUP D0 TO D1, U10 D1=0

The copy, rename, scratch, validate, initialise and format commands are common to Commodore drives and work on IEC drives too. Listing and recovering scratched files and locking files are commands of the C65's DOS, which the MEGA65 inherited, so they work only on the internal drive and on disk images (MEGA65 ROM source, dos.src). In direct mode, SCRATCH, HEADER and BACKUP first ask ARE YOU SURE? and go ahead only if the answer starts with Y; in a program they do not ask.

File names in these commands take the same patterns as DIR: * matches any characters, ? any one character, and from ROM 920314 # matches a digit and $ a letter (MEGA65 ROM change log; MEGA65 Book, p. B-71). SCRATCH "OLD*" deletes every file whose name begins with OLD, so list the same pattern with DIR first to see what it will catch.

Copying, renaming and scratching

COPY with both names on the same unit makes a second copy of a file on the same disk, under a new name. Given two different units, as in COPY "M*", U8 TO U9, it copies files from one drive to another, and COPY U8 TO U9 copies every file. The copy between units works with any mix of disk images, the internal drive and IEC drives, but it keeps the original names, and it copies only PRG, SEQ and USR files, not REL files (MEGA65 Book, p. B-59). Before writing each file, it scratches any file of the same name on the target disk (MEGA65 ROM source, COPY), so it replaces older copies without warning.

RENAME changes a single file's name; the new name must not exist already, and patterns are not allowed (MEGA65 Book, p. B-209). CONCAT adds the contents of one SEQ file to the end of another.

SCRATCH deletes every file that matches. It leaves alone locked files, files still open, and files that were never properly closed (MEGA65 ROM source, dos.src). The status message counts the files deleted: in direct mode SCRATCH prints, for example, 01, FILES SCRATCHED,04,00 for four files.

LOCK protects files from SCRATCH, and UNLOCK removes the protection. A locked file shows a < after its type in the directory. LOCK and UNLOCK appeared in ROM 920301 (MEGA65 ROM change log).

Recovering scratched files

Scratching a file does not wipe its data. The DOS clears the type byte of the directory entry, keeping a copy of it elsewhere in the entry, and marks the file's blocks as free in the BAM, the disk's map of used blocks. Until something else is written over those blocks, the file can be brought back (MEGA65 ROM source, dos.src).

DIR R lists the scratched files that can still be recovered, with a - after the type, and nothing else; it takes a pattern, as in DIR "OLD*", R. SCRATCH "OLD", R then restores the file: it puts the type back and marks the file's blocks as used again. It also takes a pattern, and its status message, 05, FILES RESTORED, counts the files restored. Both forms come from the C65 and are present in every MEGA65 ROM (MEGA65 ROM source, DIR and SCRATCH; MEGA65 Book, pp. B-71, B-234).

SCRATCH "NOTES"
DIR R               : REM SHOWS 1 "NOTES" SEQ -
SCRATCH "NOTES", R

Recover a file straight away. If a later save has reused some of its blocks, the DOS restores the file anyway, without an error (MEGA65 ROM source, dos.src), and the recovered file holds a mixture of old and new data and shares blocks with the newer file. Only files scratched by the MEGA65's DOS can be recovered this way, because only it keeps the copy of the type. A quick format (below) clears the directory, so it is not a way back either.

Checking and tidying a disk

A file that was being written when the program stopped, the machine was reset or the disk ran out of space is left as a "splat" file, shown with a * before its type. Its blocks are marked as used but its contents are incomplete, and SCRATCH will not delete it. COLLECT, the DOS's validate command, deals with it: it rebuilds the BAM from the files in the directory, deletes splat files, and frees any block that no file uses. The block count then matches the files the directory lists. The one danger is to disks with blocks a program has allocated directly, with block commands rather than files, such as boot blocks: COLLECT does not know about them and frees them too (MEGA65 Book, p. B-54).

DCLEAR sends the initialise command. The drive closes all its files and channels and reads the BAM again, and BASIC closes its channels to that unit (MEGA65 Book, p. B-64). It is the way to start afresh after a disk error.

Two commands check the data itself. DVERIFY "NAME" compares the program in memory with the file on disk, a quick check after DSAVE (MEGA65 Book, p. B-88). SET VERIFY ON makes the DOS read back every block it writes to a 3.5" disk, which catches a failing disk at the moment of saving (MEGA65 Book, p. B-238); a block that does not match is reported as 25, WRITE ERROR (MEGA65 ROM source, dos.src).

Formatting and copying whole disks

HEADER and FORMAT are the same command. With an ID, as in HEADER "GAMES", IG1, it is a full format: every track is written, and any disk or D81 image becomes an empty 1581-format disk. Without an ID it is a quick format, which works only on a disk that is already in 1581 format: it writes the new name, an empty first directory block and an empty BAM, keeping the old ID (MEGA65 ROM source, dos.src; MEGA65 Book, p. B-130). The DOS formats only 1581-format disks and D81 images; trying it on a D64 image gives 75, FORMAT ERROR (MEGA65 ROM source, dos.src).

BACKUP makes an exact copy of a whole disk, name and ID included, formatting the target as it goes. BACKUP U8 TO U9 works between the MEGA65's two managed drives, so it copies a disk image to another image, or the internal drive to an image or back. It cannot copy between a managed drive and an IEC drive; for that, use COPY U8 TO U10, which copies file by file. The form BACKUP D0 TO D1, U10 is for dual-drive units on the IEC port, which copy the disk themselves (MEGA65 Book, p. B-25).

The command channel

Channel 15 of a drive takes command strings and returns the status. BASIC 65's DISK command sends a string, as in DISK "V0", and DS and DS$ read the status (MEGA65 Book, p. B-73). The C64 way also works, and is the way to send a command to a drive that has no BASIC 65 keyword for it:

10 OPEN 15, 8, 15
20 PRINT#15, "R0:SCORES.OLD=0:SCORES"
30 INPUT#15, E, E$, T, S
40 PRINT E; E$; T; S
50 CLOSE 15

Reading the channel with INPUT# gives the four parts of the message in separate variables, so after a scratch, T holds the number of files deleted.

One caution applies to DS in a program. BASIC 65 keeps the last status message it read, and the housekeeping commands do not clear it when they run in a program (MEGA65 ROM source, trans), so DS can still show the result of an earlier command. Give CLR DS just before the command, and the next use of DS reads the drive afresh:

10 CLR DS : SCRATCH "TEMP*"
20 PRINT DS$

Subdirectories

A 1581 disk can set aside a run of whole tracks as a partition, which appears in the directory as a file of type CBM, and a partition that has been formatted is a subdirectory with its own BAM and its own list of files. The MEGA65's DOS does this for the internal drive and for D81 images, not for IEC drives. MKDIR creates and formats the partition in one step; its L argument is the size in tracks, at least 3, and each track gives 40 blocks, of which the subdirectory's own header, BAM and first directory block use some (MEGA65 ROM source, mkdir). CHDIR moves into it, and CHDIR "/" returns to the root:

MKDIR "SUB", L5      : REM FIVE TRACKS: 200 BLOCKS
CHDIR "SUB"
DSAVE "INNER"        : REM SAVED INSIDE THE SUBDIRECTORY
DIR                  : REM SHOWS ONLY INNER, AND 159 BLOCKS FREE
CHDIR "/"
DIR                  : REM SHOWS 200 "SUB" CBM

While a subdirectory is selected, every file command works inside it. After CHDIR "/" the status reads 02, SELECTED PARTITION, which is a report and not an error (tested in Xemu with ROM 920413). Chapter 14's unit 12 has subdirectories of a different kind, those of the SD card's FAT32 file system, and CHDIR with U12 moves among those.

Reading blocks directly

The DOS can also read and write single blocks, by track and sector, for programs that inspect or repair disks. Open the command channel and a second channel named #, which gives the program a buffer in the drive. U1 reads a block into the buffer, the program reads the bytes with GET#, and B-P moves the buffer's pointer to a chosen byte first. U2 writes the buffer back to a block. The numbers after U1 and U2 are the channel, the drive, the track and the sector. This program reads the header block of a 1581 disk or D81 image, track 40, sector 0, and prints the disk name from bytes 4 to 19:

10 OPEN 15, 8, 15 : OPEN 5, 8, 5, "#"
20 PRINT#15, "U1"; 5; 0; 40; 0        : REM CHANNEL, DRIVE, TRACK, SECTOR
30 INPUT#15, E, E$ : IF E THEN PRINT E; E$ : GOTO 70
40 PRINT#15, "B-P"; 5; 4              : REM POINT AT BYTE 4
50 N$ = "" : FOR I = 1 TO 16 : GET#5, A$ : N$ = N$ + A$ : NEXT
60 PRINT "DISK NAME: "; N$
70 CLOSE 5 : CLOSE 15

The name is padded to 16 characters with CHR$(160). Chapter 14 shows where the header, the BAM and the directory lie on a D81. Each directory block holds eight entries of 32 bytes, laid out as on a 1581 (Commodore 1581 Disk Drive User's Guide):

Byte Contents
0-1 In the first entry of a block only: the track and sector of the next directory block, or 0 and 255 in the last
2 File type: 0 scratched, 1 SEQ, 2 PRG, 3 USR, 4 REL, 5 CBM, with bit 7 set once the file has been closed and bit 6 set while it is locked
3-4 Track and sector of the file's first block
5-20 Name, padded with CHR$(160)
21-22 REL files: track and sector of the first side-sector block
23 REL files: record length
30-31 Size in blocks, low byte first

Writing blocks with U2 bypasses everything the DOS does to keep a disk consistent, so practise on a copy. Blocks a program claims for itself are not known to the directory, and COLLECT frees them, as noted above.

Booting Disks

There are three ways to start software from a disk (MEGA65 Book, pp. 6-9, 6-10):

  • SHIFT+RUN/STOP runs RUN "*", loading and running the first program on the disk, a convention many older Commodore disks follow.
  • BOOT loads and runs a program named AUTOBOOT.C65, the C65's convention.
  • Automatic booting. If the image or drive mounted at power-on has an AUTOBOOT.C65, it runs straight away. The configuration utility chooses the image that is mounted at power-on; this is how the Intro Disk, MEGA65.D81, starts.

Saving a short program as AUTOBOOT.C65 on that image, perhaps one that sets a font, colours and KEY macros, gives a personal start-up routine (MEGA65 Book, p. 6-10).

To make a disk of your own bootable, save its starting program as AUTOBOOT.C65. BOOT loads that file as a BASIC program and RUNs it, so a machine-language boot program needs a one-line BASIC stub that SYSes to it. To load and start a machine-language file directly, use BOOT "name", which loads the file and calls its load address (MEGA65 ROM source, BOOT).

Disk Access from Machine Language

Machine language reaches the drive through the KERNAL jump table from Chapter 11, exactly as on a C64. This routine prints the first line of a sequential file:

        lda #0          ; data and file name in bank 0
        ldx #0
        jsr $ff6b       ; SETBNK
        lda #2          ; logical file 2
        ldx #8          ; unit 8
        ldy #2          ; secondary address 2
        jsr $ffba       ; SETLFS
        lda #namelen
        ldx #<name
        ldy #>name
        jsr $ffbd       ; SETNAM
        jsr $ffc0       ; OPEN
        bcs error
        ldx #2
        jsr $ffc6       ; CHKIN: read from file 2
loop    jsr $ffcf       ; BASIN: read a byte
        cmp #13
        beq done        ; stop at the end of the line
        jsr $ffd2       ; BSOUT: print it
        jsr $ffb7       ; READST
        beq loop        ; continue while status is 0
done    jsr $ffcc       ; CLRCHN
        lda #2
        jsr $ffc3       ; CLOSE
        rts
error   rts

name    .text "SCORES,S,R"
namelen = * - name

The secondary address 2 to 14 opens a data channel; 0 and 1 are reserved for loading and saving, and 15 is the command channel, through which a program sends DOS commands and reads the status, as DISK and DS do in BASIC. SETBNK, one of the extended entries the C65 inherited from the C128, tells the KERNAL which bank the data (A) and the file name (X) are in. It must be called before OPEN, LOAD or SAVE; Chapter 11 also covers its form for 28-bit addresses.

The carry flag after OPEN reports only the KERNAL's own errors, such as too many open files or a device that does not answer. A file that is not on the disk is not one of them: OPEN succeeds, the first BASIN returns no real data, and READST is then not 0, so the routine above stops after one byte (tested from BASIC in Xemu with ROM 920413, where the byte is 0). The reason, 62, FILE NOT FOUND, waits on the drive's command channel. A routine that needs to tell the user why opens that channel as well, with a secondary address of 15 and no name, and reads the message from it with BASIN until the carriage return, exactly as the listing reads its file.

For files on the SD card outside disk images, and for loading large files into attic RAM, use the Hypervisor services described in Chapters 8 and 14 instead.

Summary

  • Units and drives. Units 8 to 11 are disk drives; managed drives handle images and the internal drive, and other units go to the IEC port. D selects the second drive of a dual unit.
  • Internal drive. A 1581-compatible 3.5" drive, mounted with MOUNT or the Freezer, using DD disks or taped HD disks, formatted with FORMAT.
  • Files. PRG for programs, SEQ and USR for sequential data, REL for random-access records, CBM for subdirectories. A USR file is a SEQ file with a different label; add ,U to the name to create one.
  • Directory. OPEN 1,8,0,"$" and GET# read the directory into a program, in the form LOAD "$" produces. MKDIR and CHDIR make and enter subdirectories on the MEGA65's own drives, and U1 with a # channel reads single blocks.
  • Status. DS and DS$ report every operation; codes below 20 mean success. In a program, give CLR DS before a housekeeping command whose result you check.
  • Housekeeping. COPY, CONCAT, RENAME, SCRATCH, LOCK, COLLECT, DCLEAR, HEADER and BACKUP each send a DOS command; DIR R lists scratched files and SCRATCH "NAME", R recovers them on the MEGA65's own drives.
  • Booting. SHIFT+RUN/STOP, BOOT and AUTOBOOT.C65.
  • Machine language. SETBNK, SETLFS, SETNAM, OPEN, CHKIN, BASIN and CLOSE work as on a C64.
