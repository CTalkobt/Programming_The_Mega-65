Programming the MEGA65 — Chapter 16: The Control Ports

Oct 4, 2026 · @Craig Taylor

Introduction

The two controller ports on the MEGA65's left side are the same 9-pin ports the C64 had, and they accept the same devices: digital joysticks, paddles, the Commodore 1351 mouse, Amiga mice and light pens. They are wired to CIA 1, as on the C64, so C64 code that reads them works unchanged. The MEGA65 adds BASIC commands for every device, and a much better way to read the keyboard, which this chapter also covers because games often use it as a controller.

Joysticks

A digital joystick has four direction switches and a fire button. Each closes a contact, and a closed contact reads as 0, so the bits are active low. The ports are read through CIA 1:

Register Port
$DC00 Port 2
$DC01 Port 1
Bit Switch, 0 when pressed
0 Up
1 Down
2 Left
3 Right
4 Fire

The same CIA registers scan the keyboard, which is why holding a joystick in port 1 can produce stray key presses, and why many C64 games use port 2.

From BASIC

JOY decodes a port for you: the low four bits give a direction from 1 (up) clockwise to 8 (up and left), 0 when centred, and each fire button adds its own bit value: 128 for button 1, the trigger, and higher values for the extra buttons described under Multi-Button Controllers below (MEGA65 Book, pp. B-143, B-144). Port 3 returns the merged state of both ports, so a game can accept a joystick in either.

10 DO
20 N = JOY(2)
30 D = N AND 15
40 IF D THEN PRINT "DIRECTION"; D;
50 IF N AND 128 THEN PRINT "FIRE!";
60 PRINT
70 LOOP

From machine language

Read the CIA register, invert it so pressed switches read as 1, and mask off the five joystick bits:

joy2    lda $dc00
        eor #$ff        ; pressed = 1
        and #$1f        ; bits 0-4: up, down, left, right, fire
        rts

A routine run with the KERNAL active should read the port when no keys are being scanned, or accept the occasional false reading; a takeover program that does its own keyboard scanning avoids the conflict entirely.

Players with a joystick in the wrong port can swap the ports from the Freezer with J, so a program only needs to support one port to be usable.

Multi-Button Controllers

The vast majority of Commodore and Atari joysticks have one fire button. Some controllers have more, and because the 9-pin port has only one fire line, the extra buttons are signalled in other ways. The MEGA65 recognises two protocols (MEGA65 Book, pp. B-143, B-144):

Protocol Buttons How the extra buttons are signalled Examples
Standard 1 The fire line only Most joysticks
Three-button Up to 3 Buttons 2 and 3 use the port's two paddle lines, POTX and POTY C64GS controller, Atari CX78 game pad, many modern pads and adapters
5plusbuttonsJoystick, by crystalct Up to 5 Buttons 2 and 3 as above; buttons 4 and 5 reuse the direction signals Five-button pads, usually with Start and Select

Controllers differ in how they label the buttons. A third button may be a second action button or one marked Start, and on five-button pads buttons 4 and 5 are typically Start and Select.

Reading the buttons from BASIC

JOY reports every button as its own bit, added to the direction:

Button Value Usual label
1 128 A, the trigger
2 256 B
3 512 C, or Start
4 1024 Start
5 2048 Select

AND isolates each button, regardless of the direction and the other buttons:

10 DO
20 N = JOY(2)
30 PRINT "DIR"; N AND 15;
40 IF N AND 128 THEN PRINT " A";
50 IF N AND 256 THEN PRINT " B";
60 IF N AND 512 THEN PRINT " C";
70 IF N AND 1024 THEN PRINT " START";
80 IF N AND 2048 THEN PRINT " SELECT";
90 PRINT
100 LOOP

Three consequences of the protocols are worth designing around:

  • Paddles confuse JOY. Buttons 2 and 3 share the paddle lines, so with paddles connected JOY may report buttons that are not pressed. Read paddles with POT instead.
  • Buttons 4 and 5 hide the stick. Because they reuse the direction signals, the stick may not register while Start or Select is held. Use them for actions taken while standing still, such as pausing, not for anything pressed during movement.
  • Not every player has extra buttons. Most Commodore joysticks have one button, so a game should be playable with button 1 alone, or offer keyboard alternatives for the other actions.

Reading the buttons from machine language

Button 1 is bit 4 of the port's CIA register, as shown earlier. Buttons 2 and 3 are the port's paddle inputs. On a C64, reading them meant selecting the port through CIA 1 and waiting for the SID to sample the lines; the MEGA65 provides registers that read each port's paddle lines directly, without any SID or CIA setup (MEGA65 Book, p. T-6):

Register Name Contents
$D620 POTAX Port A, paddle X line
$D621 POTAY Port A, paddle Y line
$D622 POTBX Port B, paddle X line
$D623 POTBY Port B, paddle Y line

A three-button controller connects button 2 to the X line and button 3 to the Y line. A released button leaves the line unconnected, so it reads as a high value near $FF, as an empty paddle input does; a pressed button pulls the line up and it reads as a low value. Treating anything below $80 as pressed gives a reliable result:

; return buttons 2 and 3 of the pad on port A in bits 1 and 2 of A
btn23   lda #0
        ldx $d620       ; POTAX: button 2
        cpx #$80
        bcs nob2        ; high: not pressed
        ora #%00000010
nob2    ldx $d621       ; POTAY: button 3
        cpx #$80
        bcs nob3
        ora #%00000100
nob3    rts

The Book names the ports A and B; press a button on a pad in each port and watch the registers to confirm which physical port each pair belongs to. Buttons 4 and 5 of the 5plusbuttonsJoystick protocol are encoded in the direction signals; JOY decodes them in BASIC, and machine language that needs them should follow the protocol's own specification.

More Joysticks and Port Options

The MEGA65 has two joystick ports and no user port, so the C64's four-player adapters, which plug into the user port, cannot be used. Games for more than two players need another input, such as the keyboard matrix described below, or players sharing a port in turn. The MEGA65 does provide some extra control over the two ports it has, in register $D612 (MEGA65 Book, pp. T-4, T-5):

Bit Name Effect when set
7 LJOYB Rotates joystick B's directions by 180 degrees, for left-handed use
6 LJOYA The same for joystick A
5 JOYSWAP Exchanges joystick ports 1 and 2

JOYSWAP is the hardware behind the Freezer's J command. Because the swap and rotation happen in hardware, they apply to every way of reading the ports, including JOY, the CIA registers and the paddle lines, so a program needs no special code to support them.

Two hardware routes go further, and both are for experimenters rather than for software meant to run on every MEGA65:

  • The J21 header. Boards from revision R4 add a 16-pin header, J21, with direct access to the joystick lines and two spare FPGA pins, intended for development work and a possible future daughter-board (MEGA65 Book, Appendix AD). Its pins are read and written through $D625-$D628, with separate data direction registers.
  • The PMOD adapter. On Nexys development boards running the MEGA65 core, a community-designed adapter adds a 9-pin joystick port through a PMOD connector (MEGA65 Book, p. 15-19).

Software that relies on either should say so clearly, since a standard MEGA65 has neither extra port.

Paddles

A paddle is a dial connected to a variable resistor, and each port takes a pair. The SID chip measures the resistance and reports it as a number from 0 to 255. Each paddle also has a fire button, read like a joystick switch.

POT reads paddles 1 to 4: the low byte is the position, and a value above 255 means the button is pressed (MEGA65 Book, p. B-197):

10 X = POT(1)
20 B = X > 255 : REM -1 WHILE THE BUTTON IS PRESSED
30 V = X AND 255 : REM POSITION, 0 TO 255

Machine language reads the two values from SID registers $D419 and $D41A, after selecting a port through the upper bits of CIA 1's port A, as on the C64.

Mice

The MEGA65 accepts the Commodore 1351 mouse, Amiga mice, and modern USB mice through adapters such as the mouSTer. The configuration utility's Input page sets the mouse type for each port: "normal" means the 1351. An Amiga mouse in a port set to normal can interfere with the keyboard (MEGA65 Book, p. 4-4).

BASIC 65 includes a complete mouse driver. MOUSE ON starts it, with a sprite as the pointer; RMOUSE reads the position and buttons; MOUSE OFF stops it:

10 MOUSE ON, 1, 1 : REM MOUSE IN PORT 1, SPRITE 1 AS POINTER
20 DO
30 RMOUSE X, Y, B
40 IF X < 0 THEN PRINT "NO MOUSE" : EXIT
50 IF B THEN PRINT "CLICK AT"; X; Y
60 LOOP
70 MOUSE OFF

The driver runs in BASIC's interrupt, so the pointer moves smoothly while the program does other work.

Light Pens

A light pen detects the moment the display's beam passes under its tip, and the video chip latches the position. LPEN(0) and LPEN(1) return the X and Y positions (MEGA65 Book, p. B-163). Light pens only work with CRT displays, so they are rarely used on the MEGA65 today.

The Keyboard as an Input Device

The C64 read its keyboard by scanning a matrix through CIA 1, which is slow, misses some combinations of keys, and produces "ghost" keys when certain keys are held together. The MEGA65 still supports CIA scanning for old software, but adds two better methods (MEGA65 Book, Appendix F).

The typing event queue

For text input, the hardware keeps a queue of typing events, already translated into characters:

Register Name Contents
$D610 ASCIIKEY The next event as ASCII; $00 if the queue is empty, $FF if it has no ASCII form
$D619 PETSCIIKEY The next event as PETSCII; $FF if it has no PETSCII form
$D60A bits 0-6 MODKEY Modifier keys held during the event
$D60A bit 7 KEYQUEUE 1 while the queue is not empty

Writing any value to $D610 or $D619 removes the event from the queue. ASCIIKEY gives access to characters PETSCII lacks, such as {, | and _, and to accented Latin-1 characters typed with the MEGA key (MEGA65 Book, pp. F-3, F-4).

wait    lda $d610       ; ASCIIKEY
        beq wait        ; $00: nothing typed yet
        sta $d610       ; remove it from the queue
        rts             ; A holds the character

The KERNAL's GETIN and BASIC's GET and GETKEY read the same queue, so a program should use one method or the other, not both.

The keyboard matrix registers

For games, which need to know which keys are held down at once, the MEGA65 exposes the C65 keyboard matrix directly. It has nine columns of eight rows (MEGA65 Book, p. F-14):

Register Use
$D614 Write a column number, 0 to 8
$D613 Read the column: a row's bit is 0 while its key is pressed
$D611 bits 0-6 Modifier keys: a bit is 1 while the key is pressed

Unlike CIA scanning, these registers report any combination of keys without ghosting, and they do not disturb the joystick ports. The Book's keyboard appendix gives the key at each row and column.

From BASIC

GET and GETKEY read the typing queue. For held keys, a BASIC program can read the matrix registers with POKE and PEEK, though the keyboard is usually simpler to treat as a source of single key presses in BASIC.

Summary

  • Joysticks. Read with JOY in BASIC, or from $DC00 (port 2) and $DC01 (port 1), active low, bits 0-4. Three-button and five-button controllers add buttons 2 to 5, which JOY reports as 256, 512, 1024 and 2048; machine language reads buttons 2 and 3 from the paddle registers $D620-$D623.
  • Paddles. POT returns position and button; machine language reads SID $D419 and $D41A.
  • Mice. Set the mouse type in the configuration utility; MOUSE ON, RMOUSE and MOUSE OFF provide a complete driver.
  • Light pens. LPEN, with a CRT display.
  • Keyboard. The typing queue at $D610, $D619 and $D60A gives characters; the matrix registers at $D614, $D613 and $D611 give held keys without ghosting.
