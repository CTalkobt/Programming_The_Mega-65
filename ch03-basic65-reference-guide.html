Programming the MEGA65 — Chapter 3: BASIC 65 Reference Guide

Oct 4, 2026 · Updated Oct 15, 2026 · @Craig Taylor

Introduction

This chapter is a reference to every keyword in BASIC 65: commands, functions, reserved variables and secondary keywords. It is meant to be consulted rather than read through. Chapter 4 shows how to use the language well, and Chapter 6 explains how BASIC 65 works internally.

The chapter has two parts. BASIC Syntax describes the parts every program is built from: numbers and literals, variables, operators, functions, expressions and statements. It ends with Error Handling, which explains how errors are reported and caught and lists every error message by number. The keyword entries follow, grouped by category, starting with Categories at a Glance.

The entries summarise the official BASIC 65 reference in the MEGA65 Book, which gives every keyword a full page or more with all parameters, remarks and examples (MEGA65 Book, Appendix B). Each entry here gives the page to turn to for the complete description. Most examples are taken from the Book's own entries, sometimes shortened; where the Book gives none, the example is written for this chapter.

In the formats, square brackets [ ] mark optional parts, and angle brackets with a slash, such as <ON / OFF>, mark a choice of one. BASIC Syntax

This section sets out the rules that every keyword is used under. It starts with the smallest parts and builds up: numbers and literals, the variables that hold values, the operators and functions that work on them, the expressions they combine into, and the statements and program lines that make up a program. It ends with what happens when a program goes wrong.

Numbers and Literals

A literal is a value written out in full in a program or command, such as 42 or "HELLO". The Book calls literals constants, because they never change while the program runs, unlike variables (MEGA65 Book, p. B-6).

Form Examples
Decimal integer 32000, -55
Decimal with a fraction 3.14, -7654.321
Decimal with an exponent 1.5E03, 7.7E-02
Hexadecimal $D020, $FF
Binary %11010010, %101
String "X", "TEXT"

The number after E is a power of ten, and says how many places to move the decimal point: 1.5E03 is 1500 and 7.7E-02 is 0.077. The symbol π is also a numeric literal, standing for pi: STR$(π) returns the digits 3.1415927 (MEGA65 Book, p. B-254).

Number prefixes

Prefix Meaning Example Book
$ Hexadecimal constant POKE $D020, 0 B-6
% Binary constant DPAT 0, 4, %00110011, %00111100, %00001111, %11110000 B-6, B-67

Both work anywhere a number does, in programs and in direct mode: PRINT $C000 prints 49152. The functions HEX$, DEC, STRBIN$ and DECBIN convert between these forms and strings at run time.

String literals

A string literal is text between double quotes. The quotes mark where it begins and ends and are not part of it, so "HELLO" has five characters. A string can hold from 0 to 255 characters (MEGA65 Book, p. B-7). It cannot contain a double quote; use CHR$(34) to add one in an expression, as in PRINT CHR$(34); "HI"; CHR$(34).

Typing the opening quote also puts the screen editor into quote mode, in which cursor movements, colour changes and other control keys are stored in the string as characters instead of acting straight away. Chapter 2 describes quote mode.

Variables

A variable is a named value that a program can change as it runs. Variables need no declaration. A numeric variable reads as 0 and a string variable as the empty string "" until a value is assigned to it (MEGA65 Book, pp. B-6, B-7):

X = 1 : PRINT X : X = X + 1 : PRINT X

A variable name follows these rules (MEGA65 Book, p. B-6):

  • It starts with a letter, and any further characters are letters or digits.
  • It can be any length, but only the first two characters count: COUNT and CO are the same variable. (The Book's own example, SPEED and SP, doesn't work in BASIC 65, because SPEED is a keyword.)
  • A type symbol may follow: %, & or $. Each type has its own set of names, so AB, AB%, AB& and AB$ are four different variables.
  • A parenthesis after the name makes it an array element, as in AB(3).
  • It cannot contain a keyword, as the next sections explain.

Type suffixes

A variable's type is set by the symbol after its name (MEGA65 Book, p. B-7):

Suffix Type Range Example
none Real (floating point) about -1E37 to 1E37 XY = 1/3
% Integer -32768 to 32767 I% = 5
& Byte 0 to 255 BY& = 23
$ String 0 to 255 characters AB$ = "TEXT"

The same characters mean different things in front of a number and after a name: %101 is a binary constant, while A% is an integer variable. A single letter followed by its type symbol, such as A, B% or C$, is a fast variable: BASIC 65 finds it without searching.

Keywords in variable names

BASIC 65 recognises keywords anywhere in a line, even inside what was meant as a variable name. A variable called SCORE contains the keyword OR, and TOTAL contains TO; both cause syntax errors. Short variable names avoid the problem, and Chapter 6 explains why one-letter names are also the fastest.

Arrays

An array holds many values of one type under one name. Each value, or element, is picked out by an index in parentheses: A(7), NA$(I), BO$(1, 2). Indexes start at 0 and can be any numeric expression, which lets a loop work through every element in turn (MEGA65 Book, p. B-7):

10 DIM NA$(2)
20 NA$(0) = "DEFT" : NA$(1) = "GARDNERS" : NA$(2) = "LYDON"
30 FOR I = 0 TO 2 : PRINT "HELLO, "; NA$(I); "!" : NEXT I

DIM sets the highest index in each dimension before the array is first used. An array used without DIM gets one dimension with indexes 0 to 10. Either way, the array's size is then fixed: DIM can't change it, and only CLR, which clears every variable, removes it. Array names are separate from other variable names, so the array A() and the variable A are unrelated. BASIC 65 sets aside memory for every element at once, so a large array can use up memory quickly (MEGA65 Book, pp. B-7, B-8).

Screen arrays

Array Contents Book
T@&(column, row) Screen code of the character at that position B-259
C@&(column, row) Colour code of the character at that position B-39

These behave as predefined byte arrays mapped onto the text screen and its colour memory. Reading one tells a program what is on the screen; assigning to one changes it, with no PEEK, POKE or address arithmetic: T@&(10,5)=1 : C@&(10,5)=2 puts a red A at column 10, row 5.

Operators

Operators are tokenised like keywords. The tables below follow the Book's operator reference (MEGA65 Book, pp. B-9 to B-12).

+ $AA Addition; positive sign; joins strings A$ = B$ + ".PRG"

>> $FE $53 Shift right A = B >> 1

The shift operators are new in BASIC 65. The two-character comparisons are stored as their two single-character tokens.

Both sides of a comparison must be the same type, either two numbers or two strings (MEGA65 Book, p. B-10). The only other operator that works on strings is +, which joins them: "MEGA" + "65" is "MEGA65".

True and false

A comparison evaluates to -1 when true and 0 when false. Because -1 has every bit set, NOT, AND, OR and XOR work the same way whether their operands are comparisons or ordinary numbers: IF X = 99 OR Y < 5 combines two conditions, while A AND 20 masks bits. The values can also be used in arithmetic: A = A - (B > 7) adds 1 to A when B is greater than 7, and leaves it unchanged otherwise (MEGA65 Book, pp. B-10, B-11).

The equals sign is both assignment and comparison, and BASIC tells them apart by position. In A = B = 10, the first = assigns and the second compares, so A becomes -1 or 0.

Precedence

From highest to lowest:

  1. ↑
  2. Unary + and -
  3. * and /
  4. Binary + and -
  5. << and >>
  6. <, <=, >, >=, =, <>
  7. NOT
  8. AND
  9. OR and XOR

Parentheses override the order: A * (A - B) * B performs the subtraction first (MEGA65 Book, p. B-12).

Functions

A function is a keyword that calculates a value from the arguments given to it in parentheses, and hands the value back to the expression it is part of. In A = SQR(16) + 1, SQR returns 4, so A becomes 5. A function call can go anywhere an expression of its type can, but it can't stand on its own as a statement.

Functions whose names end in $, such as CHR$, LEFT$ and HEX$, return strings, just as string variable names end in $. All other functions return numbers. Some keywords that are not mathematical functions work the same way, such as PEEK, JOY and POINTER.

A few functions take an argument that they ignore, because the syntax requires one. POS(0) is the usual way to write POS. Other functions, such as FRE, use their argument to choose what to return.

A program can also define its own one-line numeric functions with DEF FN and call them with FN. A function whose name is a single letter is fast, like a single-letter variable (MEGA65 Book, p. B-7).

The numeric functions are listed under Numbers and the string functions under Strings. Others are described with the statements they relate to, such as PEEK under Memory and Machine Language and RCOLOR under Colour.

Expressions

An expression is anything that has a value: a literal, a variable or array element, a function call, or any of these combined with operators and parentheses. Every expression is either numeric or a string (MEGA65 Book, p. B-4):

X = SQR(M) + PEEK(SC + J)
K$ = MID$("HI " + NA$, 1, L) + CHR$(13)

Wherever a format in this chapter names a value, such as number or string, any expression of that type will do. An expression of the wrong type gives a type mismatch error, as in KEY "POTATO", "SOUP", where KEY expects a number first (MEGA65 Book, p. B-4). Real, integer and byte values can be mixed freely in one numeric expression; to turn a number into a string, or a string into a number, use the functions STR$ and VAL.

When a value is stored in an integer or byte variable, it is first rounded down to a whole number, so A% = 2.7 stores 2 and A% = -1.5 stores -2. A whole number outside -32768 to 32767 gives an illegal quantity error. A byte variable then keeps only the low eight bits, without an error: A& = 300 stores 44, and A& = -1 stores 255.

Every value worked out along the way must also be in range. A number too large for a real gives an overflow error, and a string result longer than 255 characters gives a string too long error.

A comparison is a numeric expression too, worth -1 when true and 0 when false, as described under Operators. So a condition can be combined with arithmetic, and arithmetic can serve as a condition:

10 DA = 31 + 3 * (M = 2) + (M = 4 OR M = 6 OR M = 9 OR M = 11)
20 IF X$ = "Y" OR X$ = "N" THEN 100

Line 10 gives the number of days in month M of a year that is not a leap year. Because comparisons have a lower precedence than arithmetic but a higher one than AND and OR, a condition that leaves out a comparison can still be valid and mean something else. IF PEEK(X) = 0 AND PEEK(X + 1) = 0 tests two bytes for zero, but IF PEEK(X) AND PEEK(X + 1) = 0 ANDs the first byte with the result of the comparison.

Statements

A statement is one complete instruction. Most begin with a keyword, followed by its arguments, as in PRINT "HELLO" or POKE $D020, 0. An assignment begins with a variable instead, as in A = 5, because the word LET is optional.

The statements fall into a few broad groups, which match the categories of the keyword entries later in this chapter:

  • Assignment: LET, or a variable followed by =.
  • Program flow: IF, GOTO, GOSUB, loops, and the statements that end or pause a program.
  • Data: DIM, DATA, READ and DEF FN.
  • Input and output: INPUT, GET and PRINT for the keyboard and screen, and their # forms for files and devices.
  • Machine and devices: the statements for memory, graphics, sound, sprites and disks.
  • Comments: REM, which makes BASIC ignore the rest of the line.

Program lines and direct mode

A statement typed without a line number runs as soon as RETURN is pressed. This is direct mode. A line that starts with a number from 0 to 63999 is stored as part of the program instead, and runs when the program does (MEGA65 Book, pp. 9-6, B-4). BASIC keeps the lines in order of their numbers, whatever order they were typed in. Typing a line with an existing number replaces that line, and typing the number alone deletes it.

Several statements can share one line, separated by colons (MEGA65 Book, p. B-4):

PRINT "HELLO" : PRINT "HOW ARE YOU?"

Most statements work both in direct mode and in a program. A few, such as RENUMBER, work only in direct mode, because they act on the program itself (MEGA65 Book, p. B-5). Their entries say so.

Tokens

When a line is stored, BASIC 65 replaces each keyword with a shorter code called a token, as Chapter 6 describes. Tokens come in four forms:

  • One byte, $80 to $FD, for the keywords BASIC 65 shares with earlier Commodore BASICs and many of its own.
  • Two bytes beginning $FE, for most extended statements, a scheme BASIC 65 inherits from the C128's BASIC 7.0, such as BANK ($FE $02).
  • Two bytes beginning $CE, for most added functions, such as POINTER ($CE $0A).
  • Combinations for compound keywords, such as GOTO written as GO TO ($CB $A4) or SETBIT ($FE $2D $FE $4E, SET followed by BIT).

Reserved variables such as DS, ER and TI have no token: they are stored as their names.

Error Handling

This section describes what happens when something goes wrong in a BASIC 65 program, and how a program can deal with it. The keywords involved have their own entries under Error Handling and Debugging and Disk and Files.

How errors are reported

When BASIC 65 meets something it can't do, it stops, sends input and output back to the keyboard and screen, and prints a message ending in ERROR. If a program was running, the message gives the line, and HELP then lists that line with the failing statement highlighted (MEGA65 Book, p. B-131):

10 A = 1.E20
20 B = A + A : C = EXP(A) : PRINT A, B, C
RUN
?OVERFLOW ERROR IN 20
READY.

Each error has a number, listed under Error messages below. ER holds the number of the last error and EL its line, and ERR$(ER) gives the message text.

Catching errors in a program

TRAP sets a line for BASIC to go to when an error happens in a running program, instead of stopping (MEGA65 Book, p. B-267). The lines from there form an error handler. It reads ER and EL to find out what went wrong and where, and ends with RESUME (MEGA65 Book, p. B-213):

  • RESUME tries the failing statement again, after the handler has fixed the cause.
  • RESUME NEXT carries on with the statement after it.
  • RESUME line carries on at that line.
 10 TRAP 100
 20 FOR I = 1 TO 100
 30 PRINT EXP(I)
 40 NEXT
 50 PRINT "STOPPED FOR I ="; I
 60 END
100 PRINT ERR$(ER) : RESUME 50

Here EXP overflows when I reaches 89, and the handler prints the message and continues at line 50. A few rules follow from the way the ROM handles traps:

  • Errors in direct mode are never trapped; they are always reported.
  • While the handler runs, the trap is switched off, so an error inside the handler itself stops the program as usual. RESUME switches the trap back on.
  • Pressing RUN/STOP raises error 30, BREAK, so a program with a trap set goes to its handler instead of stopping. The STOP statement is not an error and is not trapped.
  • TRAP with no line number switches trapping off.

Disk and device errors

Not every disk problem stops the program with a BASIC error. The drive keeps its own status, which a program should check after each disk command: DS is 0 when the last disk operation worked, and DS$ gives the drive's message. Reading them also clears the error on the drive (MEGA65 Book, p. B-84):

100 DOPEN#1, "DATA"
110 IF DS <> 0 THEN PRINT "COULD NOT OPEN FILE DATA" : STOP

ST gives the status of the last input or output operation on a channel. It is 0 when all is well and is otherwise set by the device; when reading a file, a value of 64 means the end of the file was reached (MEGA65 Book, p. B-251). HELP shows only BASIC errors; for disk errors, use DS and DS$ (MEGA65 Book, p. B-131).

Finding the cause

When an error is hard to explain, HELP shows exactly which statement failed, and TRON prints each line number as it runs, so the path the program took to reach the error can be followed. Chapter 4 covers debugging BASIC programs in more depth, and Chapter 8 covers the Matrix Mode debugger.

Program Flow

DO, LOOP, WHILE, UNTIL, EXIT

Tokens $EB, $EC, $FD, $FC, $ED · Book pp. B-78, B-162, B-282, B-272, B-104

DO and LOOP enclose a block of statements that repeats. A WHILE or UNTIL condition can go after DO, tested before each pass, or after LOOP, tested after each pass; without one, the loop runs until EXIT leaves it.

Format: DO [<UNTIL / WHILE> condition] ... [EXIT] ... LOOP [<UNTIL / WHILE> condition]

10 PW$ = "" : DO
20 GET A$ : PW$ = PW$ + A$
30 LOOP UNTIL LEN(PW$) > 7 OR A$ = CHR$(13)
10 I = 0
20 DO WHILE I < 3 : PRINT I; : I = I + 1 : LOOP
30 DO : I = I - 1 : IF I = 0 THEN EXIT
40 LOOP : PRINT "DONE"

Line 20 prints 0, 1 and 2; the loop in lines 30 and 40 counts I back down and leaves through EXIT when it reaches 0.

FOR, TO, STEP, NEXT

Tokens $81, $A4, $A9, $82 · Book pp. B-114, B-266, B-252, B-178

FOR starts a counted loop and NEXT ends it. The index runs from the start value to the end value, changing by STEP each time, or by 1 if STEP is omitted. TO is also used by many other commands, such as COPY and RENAME.

Format: FOR index = start TO end [STEP step] ... NEXT [index]

10 FOR D = 0 TO 360 STEP 30
20 R = D * π / 180
30 PRINT D; R; SIN(R)

DOPEN, DCLOSE, APPEND

Tokens $FE $0D, $FE $0F, $FE $0E · Book pp. B-79, B-65, B-20

The disk-specific way to open and close files. DOPEN opens for reading, or for writing with W, or as a relative file with L and a record length. APPEND opens an existing file for writing at its end. DCLOSE closes one channel, or every file on a unit.

Format: DOPEN# channel, filename [,L reclen] [,W] [,D drive] [,U unit] / APPEND# channel, filename [,D drive] [,U unit] / DCLOSE# channel or DCLOSE [U unit]

10 DOPEN#2, "SCORES", W
20 PRINT#2, "ALICE" "," 1200
30 DCLOSE#2
40 APPEND#2, "SCORES" : PRINT#2, "BOB" "," 900 : DCLOSE#2

The comma is written as a string: a comma between PRINT# items, as in PRINT, writes spaces to the next tab stop, not a comma, and INPUT# would then read the whole line as one value.

PRINT#, INPUT#, LINE INPUT#, GET#

Tokens $98, $84, $E5 $84, $A1 # · Book pp. B-199, B-139, B-152, B-123

The file versions of PRINT, INPUT, LINE INPUT and GET, working on an open channel.

Format: PRINT# channel, arguments / INPUT# channel, variables / LINE INPUT# channel, stringvars / GET# channel, variables

20 DO : INPUT#2, N$, S : PRINT N$, S : LOOP UNTIL ST
30 DCLOSE#2
10 DOPEN#2, "NOTES", W
20 PRINT#2, "FIRST LINE" : PRINT#2, "SECOND LINE"
30 DCLOSE#2
40 DOPEN#2, "NOTES"
50 LINE INPUT#2, A$ : GET#2, B$ : PRINT A$ : PRINT B$
60 DCLOSE#2

The second program writes two lines to a new file, then reads back the whole first line with LINE INPUT# and one character of the second, S, with GET#.
