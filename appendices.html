Appendix A: Screen Codes and Colours

Screen codes

Screen codes are the values stored in screen memory, and are different from PETSCII. These are the codes of the upper-case character set; codes 128 to 255 are the same characters in reverse video.

Codes Characters
0 @
1-26 A to Z (lower-case a to z in the lower-case set)
27-31 [, £, ], ↑, ←
32 Space
33-47 ! " # $ % & ' ( ) * + , - . /
48-57 0 to 9
58-63 : ; < = > ?
64-127 Graphics characters; in the lower-case set, 65-90 are A to Z
128-255 Codes 0-127 in reverse video

To convert a letter's PETSCII code to its screen code in the upper-case set, subtract 64: PETSCII 65, A, is screen code 1. Digits and most punctuation have the same value in both. Screen codes 256 and above are used only in the VIC-IV's two-byte character modes; Chapter 12 describes them.

Colours

The first 16 palette entries are the C64's colours, used by COLOR, BORDER, BACKGROUND and colour RAM. CTRL with 1 to 8 types the first eight, and MEGA with 1 to 8 the second eight.

Code Colour Code Colour
0 Black 8 Orange
1 White 9 Brown
2 Red 10 Light red
3 Cyan 11 Dark grey
4 Purple 12 Grey
5 Green 13 Light green
6 Blue 14 Light blue
7 Yellow 15 Light grey

Entries 16 to 31 hold an alternate "rainbow" set, selected for text with ESC S and returned with ESC U, and entries 32 to 255 are free for programs to define with PALETTE.

Appendix B: PETSCII Codes

PETSCII is the character code used by PRINT, CHR$, ASC, GET and the keyboard. Codes 32 to 95 follow ASCII closely; the rest hold control codes and graphics.

Codes Contents
0-31 Control codes
32-63 Space, punctuation and digits, as in ASCII
64-95 @, letters A to Z, and [ £ ] ↑ ←
96-127 Graphics characters
128-159 Control codes
160-191 Graphics characters
192-223 The same characters as 96-127
224-254 The same characters as 160-190
255 π

In the lower-case set, 65-90 are lower-case letters and 193-218 are capitals.

Control codes

Printing these codes performs an action rather than showing a character. They can be typed into strings in quote mode, or produced with CHR$.

Code Action Code Action
5 White 129 Orange
13 Return 133-140 F1, F3, F5, F7, F2, F4, F6, F8
14 Lower-case set 141 Shifted return
17 Cursor down 142 Upper-case set
18 Reverse on 144 Black
19 Home 145 Cursor up
20 Delete 146 Reverse off
27 Escape: starts an escape sequence 147 Clear screen
28 Red 148 Insert
29 Cursor right 149-155 Brown, light red, dark grey, grey, light green, light blue, light grey
30 Green 156 Purple
31 Blue 157 Cursor left
158 Yellow
159 Cyan

These are the C64's control codes, which the MEGA65 keeps; PRINT CHR$(27); "X" sends an escape sequence, as Chapter 2 describes. The MEGA65 also defines further codes, such as for tabs and flashing text; the Book's character appendix lists them all.

Appendix C: Number Conversion

Each hexadecimal digit stands for four binary digits, so conversion between the two needs only this table:

Hex Binary Decimal Hex Binary Decimal
0 0000 0 8 1000 8
1 0001 1 9 1001 9
2 0010 2 A 1010 10
3 0011 3 B 1011 11
4 0100 4 C 1100 12
5 0101 5 D 1101 13
6 0110 6 E 1110 14
7 0111 7 F 1111 15

$D0 is therefore %11010000, and %10100101 is $A5.

Converting between hex and decimal

To convert hex to decimal, multiply each digit by its place value and add:

Place Value
1st digit from the right 1
2nd 16
3rd 256
4th 4,096
5th 65,536
6th 1,048,576
7th 16,777,216

So $D020 is 13 × 4096 + 0 × 256 + 2 × 16 + 0 = 53,280. In BASIC 65 the conversions are built in: PRINT $D020 gives 53280, PRINT HEX$(53280) gives D020, PRINT %1010 gives 10, and PRINT STRBIN$(10) gives the binary digits.

Useful values

Hex Decimal Meaning
$FF 255 Largest byte
$100 256 One page
$2000 8,192 8KB, one MAP block
$10000 65,536 64KB, one bank
$100000 1,048,576 1MB, one MAP megabyte
$8000000 134,217,728 Start of attic RAM
$FF80000 267,911,168 Start of colour RAM

Appendix F: Converting C64 and C65 Programs

Many C64 programs run unchanged in C64 mode. Converting one to MEGA65 mode lets it use the MEGA65's speed, memory and graphics, but several differences need attention.

BASIC programs

C64 MEGA65 mode
BASIC starts at $0801 BASIC starts at $2001; programs are relinked when loaded
Screen at $0400, 40 columns Screen at $0800, usually 80 columns; use PRINT, T@& and C@& rather than fixed addresses
Sprite pointers at 2040 ($07F8) Sprite pointers at $0FF8 by default; better still, use SPRITE and MOVSPR
POKE to $D000-$DFFF Works when BANK is 128, the default
Variable names that contain BASIC 65 keywords Must be renamed: BASIC 65 has many more keywords, such as COLOR, PEN and BANK
Delay loops Run about forty times faster at 40.5 MHz; replace with SLEEP or VSYNC
GET A$ : IF A$ = "" THEN ... Works, or use GETKEY
Tokens C64 BASIC tokens mean the same in BASIC 65

Machine-language programs

  • KERNAL calls through the standard jump table at $FF81-$FFF3 work unchanged, as Chapter 11 describes.
  • Zero page and system RAM are laid out differently in MEGA65 mode; code that uses C64 zero-page locations or vectors other than the documented ones needs changing, or a private base page.
  • Memory map. Code that relies on the C64's $01 banking should set it explicitly, and must allow for MAP and $D030 as Chapter 5 describes.
  • Timing. Cycle-counted code runs at 1 MHz only in C64 mode or when the CPU is slowed; at full speed it needs raster synchronisation instead.
  • STZ. 65C02 code that uses STZ to store zero needs Z held at zero, as Chapter 7 explains.
  • I/O personality. C64 code expects the VIC-II personality; MEGA65 code that writes VIC-IV registers must knock first.

C65 programs

C65 BASIC 10 programs are close relatives of BASIC 65 and often run with small changes, mostly to graphics commands, which changed between BASIC 10 and BASIC 65. C65 machine language runs on the 45GS02, which executes every 4510 instruction.

Appendix G: The Built-in Monitor

The machine-language monitor is entered with MONITOR from BASIC, by a BRK instruction, or by holding RUN/STOP while pressing reset. It accepts 32-bit addresses and treats every number as hexadecimal unless it has a prefix: + decimal, & octal, % binary, ' a PETSCII character (MEGA65 Book, Appendix O).

Command Format Purpose
A A address instruction Assemble an instruction; the monitor then offers the next address
B B address Show memory as character bitmaps
C C from to with Compare two memory ranges
D D [from [to]] Disassemble
F F from to byte Fill memory with a byte
G G [address] Jump to an address
H H from to data Hunt for bytes or text in memory
J J address Call a subroutine, as with JSR
L L "name" [, unit [, address]] Load a file into memory
M M [from [to]] Show memory as hexadecimal and text
R R Show the registers
S S "name", unit, from, to Save memory to a file
T T from to destination Transfer (copy) memory
V V "name" [, unit [, address]] Verify memory against a file
X X Return to BASIC
@ @ [command] Disk command, status or directory

Memory and registers shown by M and R can be changed by moving the cursor onto the display, typing over the values and pressing RETURN, as in other Commodore monitors. Chapter 7 walks through a first program entered with the monitor, and Chapter 8 covers debugging with it, with BRK breakpoints, and with Matrix Mode.

Appendix H: Sources and Further Reading

This book is checked against the sources below. When they disagree, the MEGA65's own source code is the final word, because it is what the machine actually runs.

Source What it contains
MEGA65 User Guide repository The source of the official MEGA65 manuals, including the MEGA65 Book (the Complete Compendium) cited throughout as "MEGA65 Book, p. X-NN". Its issue tracker and recent commits show corrections made since the August 2025 edition.
mega65-core The source code of the MEGA65 core: the VHDL that describes the 45GS02 CPU (src/vhdl/gs4510.vhdl), the VIC-IV and the other chips, the Hypervisor (src/hyppo/) and the Freezer (src/mega65-freezemenu/). The development branch has the newest changes; iomap.txt lists the I/O registers.
Dan Sanderson's MEGA65 pages Articles, tutorials and the MEGA65 Digest newsletter by a member of the MEGA65 team, including the project's history in "MEGA65: The First Ten Years".
MEGA65 ROM change log What changed in each ROM release, used to say which ROM introduced a BASIC 65 or KERNAL feature.
MEGA65 Filehost articles Articles written by MEGA65 owners and team members: short BASIC 65, DOS and assembler tips, tutorials on graphics modes, the raster rewrite buffer and DMA, and guides to setting up the hardware, SD card, cores and tools. Many were written for older ROMs and cores, so check the date and the version an article was written for before relying on it; the explanations and techniques are often still useful.

The tools used to write and test MEGA65 programs on a PC, such as the cc45 suite, other assemblers and compilers, Xemu and the MEGA65 team's transfer tools, are listed in Chapter 7, Development Tools.
